# Easy Listing

Photograph an item once, get ready-to-post listings for **eBay, Vinted, Gumtree and FB Marketplace** — with real draft/publish on eBay and a guided copy-paste flow everywhere else. Every item is kept in a local history.

**Status:** working end to end — a real listing has been published live on eBay. See [docs/STATUS.md](docs/STATUS.md) for what is done, what is left, and the gotchas already solved.

- **Live backend:** https://easy-listing-chi.vercel.app
- **Repo:** https://github.com/samuele-perrone/easy_listing (pushes to `main` auto-deploy to production)

---

## How it works

```
iPhone (SwiftUI)                    Vercel (Next.js)                 External
────────────────                    ────────────────                 ────────
take/pick photos  ──POST /api/generate──►  Claude Sonnet 5  ────────► Anthropic API
                  ◄── per-platform fields ──┘
  │
  ├─ eBay tab ────► POST /api/ebay/post ──► upload photos ─────────► Vercel Blob
  │                                     └─► create listing ────────► eBay Sell API
  │
  └─ other tabs ──► tap-to-copy each field, deep-link into their app
```

Only eBay has a public seller API. Vinted, Gumtree and FB Marketplace have none (and automating them violates their terms), so for those the app generates every field and you copy them across.

## Layout

| Path | What it is |
|---|---|
| `ios/` | SwiftUI app, iOS 17+, SwiftData for history. Project generated by XcodeGen. |
| `backend/` | Next.js App Router API on Vercel. **Vercel's root directory is set to `backend`.** |
| `docs/STATUS.md` | Progress log, decisions, eBay gotchas, next steps. **Read this when resuming.** |

### Backend endpoints

| Route | Purpose |
|---|---|
| `POST /api/generate` | Photos in → per-platform listing fields out (Claude vision, structured output) |
| `GET /api/ebay/login` → `GET /api/ebay/callback` | eBay OAuth. Tokens are handed to the app via `easylisting://` and stored in the iOS Keychain — never on the server. |
| `POST /api/ebay/refresh` | Refreshes an expired access token |
| `POST /api/ebay/post` | Uploads photos to Blob, then creates (and optionally publishes) an eBay listing |
| `POST /api/ebay/publish` | Publishes a previously saved draft offer |
| `GET/POST /api/ebay/deletion` | eBay marketplace account deletion notification — **required to keep the production keyset enabled** |
| `/privacy` | Privacy policy (eBay requires a URL) |

## Running it

### Backend

```sh
cd backend
npm install
cp .env.example .env.local     # fill in the values, see below
npm run dev
```

### iOS app

```sh
cd ios
xcodegen generate              # regenerates EasyListing.xcodeproj (gitignored)
open EasyListing.xcodeproj
```

The app defaults to the deployed backend, so it works with no configuration. Override the URL in the app's Settings screen to point at a local server.

To build and install onto a connected iPhone from the command line:

```sh
cd ios
xcodebuild -project EasyListing.xcodeproj -scheme EasyListing \
  -destination 'generic/platform=iOS' -derivedDataPath ./build \
  -allowProvisioningUpdates build

xcrun devicectl device install app --device <DEVICE_UUID> \
  ./build/Build/Products/Debug-iphoneos/EasyListing.app
```

**The phone must be unlocked** or the install fails with `kAMDMobileImageMounterDeviceLocked`.

### Deploying

Push to `main` — that's it. To deploy manually, run `npm run deploy` from `backend/` — it typechecks and deploys from the repo root. Never run `vercel deploy` from inside `backend/`; that creates a stray project, since Vercel's configured root directory is already `backend`.

## Environment variables

See `backend/.env.example`. Set on Vercel for the `production` target.

| Variable | Notes |
|---|---|
| `ANTHROPIC_API_KEY` | Preferred provider. Falls back to Gemini, then the Vercel AI Gateway. |
| `GOOGLE_GENERATIVE_AI_API_KEY` | Free-tier fallback |
| `GENERATION_MODEL` | Overrides the model when using the AI Gateway |
| `BLOB_READ_WRITE_TOKEN` | Set automatically by the attached Blob store |
| `EBAY_CLIENT_ID` / `EBAY_CLIENT_SECRET` | Production App ID and Cert ID |
| `EBAY_RU_NAME` | The **RuName**, not the App ID — they look similar and are easy to confuse |
| `EBAY_ENV` | `production` or `sandbox` (defaults to sandbox) |
| `EBAY_MARKETPLACE_ID` | `EBAY_GB` |
| `EBAY_VERIFICATION_TOKEN` / `EBAY_DELETION_ENDPOINT` | For the account-deletion webhook |
| `EBAY_LOCATION_POSTCODE` | Required to publish. Must be the **full** postcode (`SW1A 1AA`) — a partial one is accepted when the location is created but rejected at publish. |

## Safety behaviour

Nothing is published without an explicit confirmation. "Save as draft on eBay" creates an unpublished offer with no warning dialog; "Post to eBay" and "Publish draft" both show a modal stating the listing will go **live and visible to buyers** before proceeding.
